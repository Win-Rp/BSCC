# 标书查重系统 V1 用户流程与状态设计

## 1. 流程总览

V1 前台采用免登录模式，用户打开网址后直接进入查重入口。系统围绕“任务”组织核心流程，每次上传和查重生成一个任务号。1 对多付费场景额外生成订单号。

核心流程包括：

- 免费 A vs B 查重流程。
- 1 对多查重流程。
- 先查重后付费解锁流程。
- 订单/任务恢复流程。
- 文件解析失败流程。
- 支付异常流程。
- 后台订单查询与异常处理流程。
- 7 天自动清理流程。

## 2. 免费 A vs B 查重流程

### 2.1 入口

用户打开系统首页。

### 2.2 用户操作

1. 上传主标书 A。
2. 上传 1 份对比标书 B。
3. 可选输入关键字，支持逗号或换行分隔。
4. 点击开始查重。

### 2.3 系统动作

1. 创建查重任务。
2. 生成任务号。
3. 保存上传文件到任务临时目录。
4. 将任务加入队列。
5. 解析 A 文件和 B 文件。
6. 执行文本查重、格式查重、元数据查重、关键字查重。
7. 生成结果汇总和高亮定位数据。
8. 将任务状态更新为已完成。

### 2.4 结果展示

用户可免费查看：

- 总重复率。
- 完全重复率。
- 改写相似率。
- 语义相似率。
- 格式相似度。
- 元数据相似度。
- 关键字命中数。
- 重复句子数量。
- 重复段落数量。
- 左右分屏完整高亮对比。

### 2.5 异常分支

- 若 A 文件解析失败，任务失败，提示用户重新上传 A。
- 若 B 文件解析失败，任务失败，提示用户重新上传 B。
- 若 PDF 为扫描件，提示 V1 暂不支持扫描件 PDF。
- 若查重失败，页面展示失败原因，后台记录错误信息。

## 3. 1 对多查重流程

### 3.1 入口

用户打开系统首页。

### 3.2 用户操作

1. 上传主标书 A。
2. 上传 2 至 10 份对比标书 B。
3. 可选输入关键字。
4. 点击开始查重。

### 3.3 系统动作

1. 创建查重任务。
2. 生成任务号。
3. 保存上传文件到任务临时目录。
4. 将任务加入队列。
5. 解析 A 文件和全部 B 文件。
6. 对 A 与每个 B 分别执行查重。
7. 生成每个 B 的结果汇总。
8. 按总重复率从高到低排序。
9. 生成免费预览数据。
10. 将任务状态更新为待支付解锁。

### 3.4 免费可见结果

用户可免费查看：

- B 文件重复率排行榜。
- 每个 B 文件的总重复率。
- 部分重复片段预览。
- 关键字命中摘要。
- 格式相似度摘要。
- 元数据相似度摘要。

预览片段数量由后台配置。

### 3.5 付费后可见结果

用户支付成功后，可查看：

- 本次任务全部 B 文件的完整高亮详情。
- 每个 B 文件的左右分屏文档对比。
- 全部重复句子。
- 重复类型筛选。
- 点击 A 片段后 B 文档自动跳转。

## 4. 先查重后付费解锁流程

### 4.1 触发条件

当用户上传 2 至 10 份 B 文件时，系统识别为 1 对多查重任务。

### 4.2 支付前状态

查重完成后，任务进入待支付解锁状态。

页面展示：

- 任务号。
- B 文件数量。
- 重复率排行榜。
- 部分重复片段预览。
- 支付金额。
- 客服微信/邮箱。
- 提示文案：付费后解锁本次 1 对多结果。

### 4.3 用户操作

1. 填写联系方式。
2. 点击解锁完整结果。
3. 系统生成订单。
4. 页面显示支付宝扫码支付二维码。
5. 用户扫码支付。

### 4.4 系统动作

1. 根据 B 文件数量和后台单价计算金额。
2. 创建订单号。
3. 将订单与任务绑定。
4. 调用支付宝接口生成扫码支付信息。
5. 前台轮询支付状态。
6. 支付宝回调后，后端验签并更新订单状态。
7. 支付成功后，将任务解锁状态更新为已解锁。

### 4.5 支付成功

页面自动进入完整结果视图，用户可查看本次任务全部 B 文件的完整高亮详情。

### 4.6 支付失败或超时

页面展示：

- 订单号。
- 任务号。
- 支付状态。
- 重新支付入口。
- 客服微信/邮箱。

用户可稍后通过订单号或任务号恢复。

## 5. 订单/任务恢复流程

### 5.1 入口

用户进入订单/任务恢复页面。

### 5.2 查询方式

系统支持以下查询方式：

- 任务号。
- 订单号。
- 联系方式 + 任务号。
- 联系方式 + 订单号。

### 5.3 系统动作

1. 校验查询参数。
2. 查找任务或订单。
3. 判断任务是否存在。
4. 判断任务是否过期。
5. 判断任务是否已删除。
6. 判断订单是否支付成功。
7. 返回可恢复页面。

### 5.4 可恢复状态

- A vs B 免费任务：7 天内可恢复完整结果。
- 1 对多未支付任务：7 天内可恢复免费预览和支付入口。
- 1 对多已支付任务：7 天内可恢复完整高亮结果。

### 5.5 不可恢复状态

- 任务已过期。
- 任务数据已删除。
- 任务号或订单号不存在。
- 联系方式校验失败。

不可恢复时，页面展示客服微信/邮箱。

## 6. 文件解析失败流程

### 6.1 单份 A vs B

若 A 或 B 文件解析失败：

1. 任务状态更新为已失败。
2. 页面提示具体失败文件。
3. 页面提示失败原因。
4. 用户可重新上传后发起新任务。
5. 后台记录错误信息。

### 6.2 1 对多

若 A 文件解析失败：

1. 整个任务失败。
2. 页面提示主标书 A 解析失败。
3. 用户可重新上传后发起新任务。

若部分 B 文件解析失败：

1. 失败的 B 文件标记为解析失败。
2. 其他 B 文件继续查重。
3. 结果页展示成功文件结果。
4. 结果页展示失败文件列表和原因。
5. 后台记录每个失败文件的错误信息。

## 7. 后台订单查询与异常处理流程

### 7.1 管理员登录

1. 管理员打开后台登录页。
2. 输入账号密码。
3. 系统校验成功后进入后台。
4. 校验失败时提示账号或密码错误。

### 7.2 查询订单

管理员可按以下条件查询订单：

- 订单号。
- 任务号。
- 支付状态。
- 联系方式。
- 创建时间。
- 支付时间。

订单详情展示：

- 订单号。
- 任务号。
- 支付状态。
- 支付金额。
- B 文件数量。
- 用户联系方式。
- 查重状态。
- 错误信息。
- 创建时间。
- 支付时间。
- 过期时间。
- 文件名列表。

### 7.3 查询任务

管理员可按以下条件查询任务：

- 任务号。
- 任务状态。
- 文件名。
- 创建时间。
- 过期时间。

任务详情展示：

- 上传文件列表。
- 解析状态。
- 查重状态。
- 支付解锁状态。
- 结果保留状态。
- 错误信息。

### 7.4 异常处理

管理员可执行：

- 手动标记已支付。
- 手动重新发起查重。
- 手动延长结果保留时间。
- 手动删除任务数据。

每次后台操作应记录操作日志。

## 8. 7 天自动清理流程

### 8.1 清理触发

系统通过定时任务定期扫描过期任务，建议每日执行一次。

### 8.2 清理条件

满足以下条件的任务进入清理流程：

- 当前时间超过任务过期时间。
- 任务状态不是已删除。

### 8.3 清理内容

系统删除：

- 原文文件。
- 解析文本。
- 高亮结果。
- 临时任务数据。

系统保留：

- 订单基础记录。
- 支付金额。
- 支付状态。
- 任务号。
- 订单号。
- B 文件数量。
- 创建时间。
- 支付时间。
- 基础异常摘要。

### 8.4 清理后状态

任务状态更新为已删除或已过期。

用户再次恢复时，系统提示任务已过期，结果数据已删除，并展示客服微信/邮箱。

## 9. 任务状态机

### 9.1 状态列表

- `created`：待上传。
- `uploaded`：已上传。
- `queued`：排队中。
- `parsing`：解析中。
- `checking`：查重中。
- `awaiting_payment`：待支付解锁。
- `completed`：已完成。
- `failed`：已失败。
- `expired`：已过期。
- `deleted`：已删除。

### 9.2 常见状态流转

免费 A vs B：

```text
created -> uploaded -> queued -> parsing -> checking -> completed
```

1 对多未支付：

```text
created -> uploaded -> queued -> parsing -> checking -> awaiting_payment
```

1 对多支付成功：

```text
created -> uploaded -> queued -> parsing -> checking -> awaiting_payment -> completed
```

任务失败：

```text
created/uploaded/queued/parsing/checking -> failed
```

任务过期清理：

```text
completed/awaiting_payment/failed -> expired -> deleted
```

## 10. 支付状态机

### 10.1 状态列表

- `created`：订单已创建。
- `pending`：待支付。
- `paid`：已支付。
- `failed`：支付失败。
- `closed`：订单关闭。
- `refunded`：已退款，V1 可预留。

### 10.2 常见状态流转

正常支付：

```text
created -> pending -> paid
```

支付失败：

```text
created -> pending -> failed
```

订单关闭：

```text
created -> pending -> closed
```

后台手动处理：

```text
pending/failed/closed -> paid
```

## 11. 前台页面合并建议

V1 不强制每个功能独立页面，可合并为：

- 首页：上传、关键字输入、任务提交。
- 任务页：进度、结果汇总、支付入口、文档对比。
- 恢复页：订单/任务查询。
- 帮助区：客服微信/邮箱和基础说明。

## 12. 后台页面合并建议

V1 不强制每个功能独立页面，可合并为：

- 后台登录页。
- 后台工作台：订单列表、任务列表、详情抽屉。
- 配置页：单价、客服信息、查重参数。
- 清理页：过期任务、手动删除、延长保留。
