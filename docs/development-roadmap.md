# 标书查重系统 V1 AI 开发路线图

## 1. AI 开发原则

本项目计划主要使用 AI 完成开发，因此需要将任务拆成边界清晰、可验证、可回滚的小阶段。

开发原则：

- 每个阶段只解决一类问题。
- 每个阶段都要有可运行结果。
- 先实现 Mock 和基础闭环，再逐步替换真实能力。
- 支付、查重算法、文档解析等高风险模块单独开发和测试。
- 每次让 AI 开发前，明确引用需求文档、流程文档、API 文档和数据库文档。

## 2. 推荐技术栈

V1 推荐：

- 前端：Vue 3 + Vite + TypeScript。
- 后端：Python FastAPI。
- 数据库：SQLite。
- ORM：SQLAlchemy 或 SQLModel。
- 异步任务：后端内置 worker 队列，V1 暂不引入复杂消息队列。
- 文件解析：`python-docx`、PDF 文本提取库。
- 支付：先做支付宝 Mock，再接真实支付宝扫码支付。
- 部署：单机部署，前后端同服务器。

## 3. 阶段 0：项目约束与文档冻结

目标：

- 确认 V1 范围。
- 冻结第一版需求文档。
- 统一开发上下文。

输入文档：

- `docs/requirements.md`
- `docs/user-flows.md`
- `docs/database-schema.md`
- `docs/api-spec.md`

产出：

- 明确 V1 不做历史库、不做 OCR、不做报告导出、不做普通用户登录。
- 确认数据库使用 SQLite。

验收：

- 所有后续开发任务都能引用同一组文档。

## 4. 阶段 1：项目脚手架

目标：

- 创建前后端项目结构。
- 后端能启动。
- 前端能启动。
- 前后端能完成一次健康检查。

后端任务：

- 创建 FastAPI 项目。
- 增加配置模块。
- 增加 SQLite 连接。
- 增加基础日志。
- 增加 `/api/health` 接口。

前端任务：

- 创建 Vue 3 + Vite 项目。
- 增加基础路由。
- 增加 API 请求封装。
- 增加健康检查页面。

验收：

- 后端启动成功。
- 前端启动成功。
- 前端能请求后端 `/api/health`。

## 5. 阶段 2：数据库与后台管理员基础

目标：

- 落地 SQLite 表结构。
- 支持管理员登录。
- 支持系统配置读取和修改。

后端任务：

- 实现数据库迁移或初始化脚本。
- 创建 `admin_users`、`settings`、`operation_logs` 表。
- 实现管理员登录。
- 实现配置读写接口。
- 初始化默认管理员和默认配置。

前端任务：

- 后台登录页。
- 后台配置页。

验收：

- 管理员可登录后台。
- 可修改每份 B 文件单价。
- 可修改预览片段数量。
- 可修改客服微信和邮箱。
- 修改配置后前台接口能读取最新配置。

## 6. 阶段 3：文件上传与任务创建

目标：

- 用户可上传 A 文件和 B 文件。
- 系统创建任务并返回任务号。
- 文件保存到任务目录。

后端任务：

- 实现 `/api/tasks`。
- 校验 B 文件数量 1 至 10。
- 校验文件扩展名。
- 创建 `tasks` 和 `task_files` 记录。
- 保存文件到 `storage/tasks/{task_no}/uploads/`。

前端任务：

- 首页上传区域。
- A 文件选择。
- 多个 B 文件选择。
- 关键字输入。
- 提交后进入任务页。

验收：

- 上传 1 个 A 和 1 个 B 可创建 `single` 任务。
- 上传 1 个 A 和多个 B 可创建 `multi` 任务。
- 超过 10 个 B 文件时前端和后端都能提示。

## 7. 阶段 4：任务队列与状态轮询

目标：

- 任务进入队列。
- 前台能看到排队、解析、查重、完成、失败状态。

后端任务：

- 实现简单内存队列或后台 worker。
- 实现任务状态流转。
- 实现 `/api/tasks/{task_no}/status`。
- 实现失败状态和错误信息记录。

前端任务：

- 任务状态页。
- 轮询任务状态。
- 展示进度和失败原因。

验收：

- 用户提交任务后能看到状态变化。
- 任务失败时页面有明确提示。

## 8. 阶段 5：Word/PDF 基础解析

目标：

- 能解析 `.docx` 和可复制文本 PDF。
- 能识别并提示不支持的扫描 PDF。

后端任务：

- 实现 Word 文本提取。
- 实现 PDF 文本提取。
- 实现基础分段、分句。
- 保存解析文本和结构化 JSON。
- 更新 `task_files` 解析状态。

验收：

- 普通 Word 能解析出文本。
- 可复制文本 PDF 能解析出文本。
- 扫描 PDF 能给出 V1 暂不支持提示。
- 解析失败原因能在后台看到。

## 9. 阶段 6：基础 A vs B 查重

目标：

- 先实现可用的文本查重闭环。
- 支持完全重复、基础相似、重复率计算。

后端任务：

- 实现句子级切分。
- 实现完全重复检测。
- 实现基础文本相似度检测。
- 计算主重复率、句子重复率、段落重复率。
- 生成 `compare_results` 和 `matched_segments`。

前端任务：

- 结果汇总页。
- 展示 A 文件名、B 文件名、总重复率、重复句子数、重复段落数。

验收：

- 两份有明显重复内容的文档能识别重复句子。
- 两份明显不同的文档重复率较低。
- A vs B 免费结果可完整查看。

## 10. 阶段 7：左右分屏高亮对比

目标：

- 实现核心交互：A 文档高亮，点击后 B 文档跳转。

后端任务：

- 实现 `/api/tasks/{task_no}/results/{compare_result_id}/detail`。
- 返回文档结构块和匹配定位数据。

前端任务：

- 左右分屏文档对比组件。
- 不同类型高亮颜色。
- 点击 A 片段定位 B 片段。
- 支持切换 B 文件。

验收：

- A vs B 能完整高亮。
- 点击 A 中重复句子，右侧 B 能跳转到对应内容。
- 高亮颜色能区分匹配类型。

## 11. 阶段 8：1 对多结果与预览锁定

目标：

- 支持最多 10 份 B 文件。
- 1 对多按重复率排序。
- 未支付时只展示排行榜和预览片段。

后端任务：

- 对每个 B 分别生成 `compare_results`。
- 按总重复率排序。
- 根据后台配置生成免费预览片段。
- 对 `multi` 模式完整详情加支付校验。

前端任务：

- B 文件排行榜。
- 预览片段展示。
- 锁定状态提示。
- 解锁按钮。

验收：

- 1 对多结果按重复率排序。
- 未支付时不能访问完整详情。
- 免费预览数量受后台配置控制。

## 12. 阶段 9：关键字查重

目标：

- 支持用户手动输入关键字。
- 文档中高亮关键字命中。

后端任务：

- 解析逗号和换行分隔的关键字。
- 执行关键字匹配。
- 写入 `keyword_hits`。
- 在详情接口返回关键字命中数据。

前端任务：

- 关键字输入框。
- 关键字命中摘要。
- 文档中关键字高亮。

验收：

- 输入多个关键字能正确命中。
- 命中次数和位置可展示。

## 13. 阶段 10：格式与元数据对比

目标：

- 展示格式相似项和元数据相似项。

后端任务：

- 提取作者、创建时间、修改时间、软件、模板来源等元数据。
- 对比相同/相近字段。
- 提取标题层级、段落数量、页眉页脚、字体样式、目录结构等格式信息。
- 写入 `metadata_results` 和 `format_results`。

前端任务：

- 结果页展示元数据对比。
- 相同/相近字段高亮。
- 展示格式相似项。
- 元数据缺失时提示无法判断。

验收：

- 元数据字段能展示。
- 相同或相近字段能高亮。
- 缺失字段能提示无法判断。

## 14. 阶段 11：支付 Mock 与订单恢复

目标：

- 在不接真实支付宝前，先跑通支付解锁闭环。

后端任务：

- 实现 `/api/orders`。
- 实现 `/api/orders/{order_no}/status`。
- 实现 Mock 支付成功接口。
- 实现 `/api/recover`。
- 订单支付成功后解锁任务。

前端任务：

- 支付弹窗。
- 联系方式填写。
- 订单号展示。
- 支付状态轮询。
- 恢复页。

验收：

- 1 对多任务可创建订单。
- Mock 支付成功后可查看完整详情。
- 通过任务号/订单号可恢复结果。

## 15. 阶段 12：真实支付宝扫码支付

目标：

- 接入支付宝扫码支付。

后端任务：

- 接入支付宝配置。
- 生成扫码支付二维码。
- 实现支付宝异步回调。
- 完成验签。
- 支付成功后更新订单并解锁任务。

前端任务：

- 展示支付宝二维码。
- 轮询订单状态。
- 支付成功后自动进入完整结果。

验收：

- 用户可扫码支付。
- 支付成功后系统自动解锁结果。
- 支付失败或关闭页面后可通过订单号恢复。

## 16. 阶段 13：后台订单与任务管理

目标：

- 管理员可以查询和处理异常。

后端任务：

- 订单列表和详情接口。
- 任务列表和详情接口。
- 手动标记已支付。
- 重新发起查重。
- 延长结果保留时间。
- 手动删除任务数据。
- 操作日志记录。

前端任务：

- 后台工作台。
- 订单列表和详情。
- 任务列表和详情。
- 异常处理按钮。
- 操作日志查看。

验收：

- 管理员能按订单号查询任务。
- 管理员能手动标记已支付。
- 管理员能重新发起查重。
- 管理员能删除任务数据。

## 17. 阶段 14：7 天清理任务

目标：

- 自动删除过期临时数据，仅保留订单基础记录。

后端任务：

- 实现清理脚本。
- 定时扫描过期任务。
- 删除任务文件目录。
- 更新任务状态。
- 保留订单基础记录。

验收：

- 过期任务文件能被删除。
- 订单基础记录仍可在后台查看。
- 用户恢复过期任务时提示已过期。

## 18. 阶段 15：测试与上线准备

目标：

- 完成 V1 验收测试。
- 准备部署。

测试用例：

- A vs B 完全不同。
- A vs B 部分重复。
- A vs B 完全重复。
- A vs 多 B，3 至 10 份文件。
- 关键字命中。
- PDF 可解析。
- 扫描 PDF 提示不支持。
- 支付成功解锁。
- 支付失败恢复。
- 后台手动标记已支付。
- 7 天清理。

上线准备：

- 配置生产数据库路径。
- 配置存储目录。
- 配置管理员账号。
- 配置支付宝参数。
- 配置客服微信和邮箱。
- 配置备份策略。

验收：

- 满足 `docs/requirements.md` 中的 V1 验收标准。
