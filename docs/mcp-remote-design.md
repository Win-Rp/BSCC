# BSCC MCP 远程多用户接入设计

当前交付的是本地 stdio 适配器。远程版需要解决文件传递、用户身份、任务归属及网页链接授权，然后再提供 Streamable HTTP 端点。

## 身份与任务归属

- MCP 服务作为 OAuth 2.1 资源服务器，验证签发方、受众、有效期和权限范围；身份提供方负责登录、授权和签发令牌。
- 任务和临时上传记录增加不可变的用户或组织归属。创建、状态、摘要、预览、详情、原文件、恢复和订单等入口均在后端校验归属，不能只在 MCP 适配器校验。
- 现有任务号是定位符，不作为身份凭证。已有匿名任务不能仅凭任务号自动绑定到账号；需要另行设计所有权证明或经授权的人工迁移流程。
- 定义 `tasks:create`、`tasks:read`、`tasks:detail` 和 `uploads:write` 等最小权限；详情继续执行原有免费额度和支付解锁检查。

## 文件上传

- 为登录用户创建短期上传会话，返回限定大小、文件类型和有效期的上传目标；上传完成后返回与用户绑定的 `upload_id`。
- MCP 创建工具只接受该用户的 `upload_id`，后端验证归属、数量和文件内容，再调用现有任务处理流程。上传需支持真正的文件传输，不依赖客户端本地路径，也不接受任意公网 URL 供服务端抓取。
- 临时上传与任务创建支持去重或幂等键；明确超时后查询创建结果的方法，避免重复任务。过期、失败和未使用的临时文件需要清理。

## 网页链接和生命周期

- 返回 HTTPS 结果页与对比页链接，并要求浏览器登录后按任务归属授权；不要把 OAuth 访问令牌放入 URL。需要跨客户端打开时，可设计短期、单次、用户绑定的兑换凭证。
- 结果与原文按站点配置的 `expires_at` 过期；实现并监控后端的原文、解析文件、临时上传及结果清理。日志保留任务标识和错误码，避免正文、关键词及凭证。
- MCP 详情按现有分页接口读取，保持未解锁任务的预览和详情边界；支付仍由网站流程完成。

## 上线验证

验证两个用户之间的任务、文件、订单和结果不可互访；覆盖 OAuth 过期与权限不足、临时上传过期、创建重试、文件大小上限、支付解锁、网页链接登录和数据清理。通过后再开放远程 Streamable HTTP 端点。
